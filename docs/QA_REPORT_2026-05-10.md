# AHO QA Bug-Hunt Report — 2026-05-10

Method: source-code review across `/src/app`, `/src/components`, `/src/lib`,
`/src/middleware.ts`, migrations, manifests, and message catalogs. Live-site
HTTP probing was unavailable in this sandbox (no outbound network), so all
findings are derived from static analysis. Browser-only behaviour
(layout polish, JS race conditions, real Stripe redirects, real Meta OAuth)
is flagged in the "couldn't test" section.

---

## P0 — broken (blocks the flow)

1. **`searchListings` exact-match on `city` will silently return zero results
   when DB casing differs from URL value.**
   `src/lib/listings/search.ts:154` uses `query.eq('city', filters.city)` while
   the parallel `searchCityLanding` helper at `:285` uses `.ilike()`. The hero
   form on the homepage submits the city display name from the dropdown
   (`/search?city=Santo Domingo` etc.); if any agent saved a row as
   `santo domingo` (no caps), the result page reports zero hits even though
   listings exist.
   **Repro**: From `/`, pick country DR, pick a city, submit; if any DB row
   diverges in case, the search returns empty.
   **Fix**: Switch line 154 to `query.ilike('city', filters.city)` (mirror the
   city-landing helper) — or normalize on insert.

2. **Lead-routing redirect builds the wrong ES path → 404 after sign-in.**
   `src/app/[locale]/dashboard/leads/routing/page.tsx:162` redirects
   unauthenticated ES visitors to
   `?next=/es/panel/contactos/routing`, but the ES path registered in
   `PATHNAMES` is `/panel/contactos/enrutamiento`
   (`src/i18n/config.ts:138`). After signin, the user lands on a 404.
   **Fix**: Use `enrutamiento` (or call `getPathname()` from
   `@/i18n/routing`) instead of the literal `routing` segment.

3. **Photo-import-failures GET endpoint 500s on a non-UUID property id.**
   `src/app/api/properties/[id]/import-photos/failures/route.ts:48` passes the
   raw `propertyId` straight into PostgREST `eq('property_id', propertyId)`.
   Postgres returns 22P02 for a non-uuid value; the route logs and returns
   500 instead of 400/404.
   **Fix**: Validate with `z.string().uuid().safeParse(...)` (the sibling
   `favorite/route.ts` does this).

4. **Locked "New listing" button still navigates.**
   `src/app/[locale]/dashboard/properties/page.tsx:147` renders an `<a>`
   with `href={atCap ? '#' : path}` and `aria-disabled={true}`. Browsers
   ignore aria-disabled on anchors — clicking still navigates to `#` (or
   the new-listing form, since `#` would just scroll). At-cap users can
   still hit the form; `pointer-events-none` or rendering as `<button
   disabled>` is needed.
   **Fix**: Render a real `<button disabled>` or add `pointer-events: none;
   cursor-not-allowed`.

5. **Robots.txt does not disallow `/search` or `/admin` for marketing
   locales (PL/PT/DE/FR/IT).**
   `src/app/robots.ts:40-47` only blocks `/en/search`, `/es/buscar`, and
   `/en|es/admin/`. `/pl/search`, `/pt/search`, `/de/search`, `/fr/search`,
   `/it/search` — and the corresponding `/admin/` trees — are crawled and
   indexed, exactly the "infinite faceted-URL crawl" loop §16.7 of the
   spec calls out. Admin URLs are auth-gated but their existence still
   leaks via SERP snippets.
   **Fix**: Generate disallow rules from `LOCALES`; cover both the
   `/search` and `/admin/` subtrees in every locale.

6. **`PATHNAMES` declares routes that have no page file** for `/admin/*`
   subpaths in non-EN/ES locales: only `/admin` is registered (line 201),
   but `/admin/orgs`, `/admin/leads`, `/admin/users`, `/admin/reviews`
   pages exist as routes that next-intl doesn't know about. Visiting
   `/de/admin/users` works as a non-pathname-aware path but the locale
   switcher's `getPathname()` falls back to home (`locale-toggle.tsx:113`)
   for these surfaces.
   **Fix**: Register the full admin subtree in `PATHNAMES` (single-string
   variant; admin URLs aren't localized) so the locale switcher resolves
   them cleanly.

## P1 — wrong (works but misleading / risky)

7. **Locale path branching only checks `=== 'es'`** in 23+ files, defaulting
   PL/PT/DE/FR/IT to the English path. Examples:
   - `src/app/[locale]/page.tsx:35-36`
   - `src/app/[locale]/dashboard/layout.tsx:40,42,53,63,67-75`
   - `src/components/listings/favorite-button.tsx:62`
   - `src/components/saved-searches/save-search-button.tsx:32-33`
   - `src/lib/listings/search.ts:785` (`buildSearchUrl`)
   - `src/app/[locale]/saved-properties/page.tsx:58-59,65`
   - `src/app/[locale]/saved-searches/page.tsx:52-53,64`
   - `src/app/[locale]/properties/[slug]/page.tsx:184,366,370` (lots)
   This is intentional per CLAUDE.md (marketing locales fall back to EN
   slugs) but it's spread across the codebase rather than centralised; any
   future localized segment needs a code-grep + manual update. Risk: easy
   to introduce an inconsistency (saved-searches page redirect uses
   `busquedas-guardadas` but a freshly-added file might forget).
   **Fix**: Centralise via `getPathname()` from `@/i18n/routing` everywhere.

8. **`translatePathForLocale` only matches EN/ES prefixes.**
   `src/lib/auth/translate-path.ts:31` regex: `^\/(en|es)`. PL/PT/DE/FR/IT
   user's `next` path coming from a recovery email is returned unchanged,
   so a user whose `user_metadata.locale === 'pl'` still lands on the EN
   surface after an email-link sign-in.
   **Fix**: Use the full `LOCALES` set in the regex AND in the
   `userLocale !== 'en' && userLocale !== 'es'` guard at
   `auth/callback/route.ts:202`.

9. **City-landing canonical + hreflang only know EN/ES.**
   `src/app/[locale]/properties-in/[country]/[city]/page.tsx:79-90` builds
   `canonical = es ? esPath : enPath` and the languages map only has
   `en`/`es`/`x-default`. PL/DE/FR/IT/PT visitors see a canonical
   pointing to the EN surface (Google may de-rank the localized URL) and
   no hreflang entries for their language.
   **Fix**: When emitting alternates, iterate over `LOCALES` even if the
   slug is identical for marketing locales.

10. **i18n drift: marketing locale catalogs are 39–60% the size of EN.**
    `messages/de.json`, `it.json`, `pt.json` are ~640 lines vs en.json's
    1601. With the deep-merge fallback, large stretches of UI render in
    English to those visitors. Dashboard, property detail, contact form
    error strings all fall through.
    **Fix**: Per design tradeoff, but the gap is wider than the
    "translate the parts that matter for SEO" intent. Audit which
    untranslated keys are user-visible and prioritise those.

11. **Hardcoded English in import-panel (URL + voice import).**
    `src/components/listings/import-panel.tsx` has dozens of literal
    English strings: "Importing…", "Use this recording", "Re-record",
    "Skip — fill the form manually", every option-card body, every error
    message in `translateUrlError` / `translateVoiceError`. The
    new-listing flow is a high-value agent surface; ES agents see English
    everywhere.
    **Fix**: Move to `useTranslations('importPanel')` — define an
    `importPanel` namespace in `messages/{en,es}.json`.

12. **Lead routing page also hardcodes EN/ES via inline `TXT` constant**
    (`src/app/[locale]/dashboard/leads/routing/page.tsx:60-110`) plus
    a non-localized metadata title "Lead routing · Dashboard · AHO" at
    line 16. Other locales fall through to EN.
    **Fix**: Move to message catalog; use `getTranslations` + `generateMetadata`.

13. **Auth-error page hardcoded eyebrow line.**
    `src/app/[locale]/auth/error/page.tsx:45` — `locale === 'es' ?
    'Error de autenticación' : 'Auth error'`. PL/PT/DE/FR/IT users see
    English.
    **Fix**: Add `auth.error.eyebrow` key to messages and use it.

14. **error.tsx eyebrow hardcoded "Error".**
    `src/app/[locale]/error.tsx:38` — string literal "Error" not
    translated. ES locale shows "Error" verbatim (which happens to work
    in Spanish too, lucky), other locales would show English.

15. **Property detail page hardcodes Call/Speaks labels.**
    `src/app/[locale]/properties/[slug]/page.tsx:523, 559` — `'Idiomas'
    : 'Speaks'` and `'Llamar' : 'Call'`. PL/PT/DE/FR/IT users see English
    labels in the agent contact card.
    **Fix**: Add `property.speaksLabel` / `property.callLabel` to messages.

16. **SaveSearchButton stores `'en'` for any non-ES locale.**
    `src/components/saved-searches/save-search-button.tsx:66` — saved
    `locale: locale === 'es' ? 'es' : 'en'`. A Polish buyer who saves a
    search has the row tagged EN; future email alerts will be in
    English even though they were browsing in Polish.
    **Fix**: Pass the active locale through. (Schema may need to widen
    its accepted values.)

17. **Saved-searches page metadata + headers hardcoded English.**
    `src/app/[locale]/saved-searches/page.tsx:24` (`title: 'Saved
    searches · AHO'`) and `:83` (`'Tu cuenta' : 'Your account'`).
    **Fix**: Use `generateMetadata` + i18n keys.

18. **Contact form Send button is silently disabled while Turnstile loads
    or fails.** `src/components/listings/contact-form.tsx:186` —
    `disabled={isSubmitting || (turnstileRequired && !captchaToken)}`.
    No helper text, no "checking…" state, no error if the widget fails
    to load (e.g. CSP blocks the script). The user sees a greyed-out
    button and assumes the page is broken.
    **Fix**: Render explicit "verifying you're human…" copy below the
    widget; if the widget errors, surface that to the user instead of
    silently leaving the button disabled forever.

19. **Favorite analytics fan-out is asymmetric.**
    `src/app/api/properties/[id]/favorite/route.ts` records
    `favorite_add` (line 114) but does NOT record any event on the
    delete (toggle-off) path (lines 80-91). Per-property analytics will
    over-count favorites because the toggles cancel out only in the UI,
    not in the event log.
    **Fix**: Record `favorite_remove` (will need to add the enum value
    to migration 0027 if not present) or skip both for symmetry.

20. **`fetchModerationQueue` always returns `agentSlug: null`.**
    `src/lib/reviews/queries.ts:207` — code comment defers it to v1.1.
    Result: admin reviews UI cannot link to the agent's profile; the
    "click into agent profile" reviewer flow described in the QA brief
    is non-functional.
    **Fix**: Add the second join via `organization_members` →
    `organizations.public_slug ?? slug`.

21. **Admin-leads page dumps lead PII (email + phone) without any masking
    and without an i18n layer.**
    `src/app/[locale]/admin/leads/page.tsx:187-189` — every cross-org
    lead's email + phone is rendered in plain text to every admin. No
    masking, no audit trail of who viewed what. Combined with the
    "every admin reads everything" model, this makes /admin/leads a
    juicy target for an admin-account compromise.
    **Fix**: Mask by default (`b…@example.com`) with click-to-reveal that
    writes an audit log row. Same treatment on phones.

22. **Admin orgs page links to a public profile that may 404.**
    `src/app/[locale]/admin/orgs/page.tsx:142` links every org name to
    `/{locale}/agents/{slug}`. New orgs without active+published
    listings 404 there per
    `migrations/0031_organizations_public_select_with_active_listings.sql`.
    **Fix**: Either link to a placeholder admin-org-detail page, or
    detect zero-listing orgs and skip the link.

23. **Admin overview links org names to `/agents/{slug}` (legacy slug).**
    `src/app/[locale]/admin/page.tsx:627` — uses `org.slug` not
    `public_slug`, so every click triggers a 301 round-trip. Same 404
    risk as #22 for newly-onboarded orgs.

24. **`/admin/users` issues 500 round-trips per render for membership
    counts.** `src/app/[locale]/admin/users/page.tsx:88-96` does an
    N+1 — one HEAD count per user, up to 500 users.
    **Fix**: Replace with a single GROUP BY query (e.g. RPC) that
    returns counts keyed by user id.

25. **`/admin/orgs` does the same N+1 at 2× factor.**
    `src/app/[locale]/admin/orgs/page.tsx:67-87` — for each of up to 500
    orgs, two HEAD counts in parallel. Up to 1000 round-trips per page
    render.
    **Fix**: Single query with two `count(*) FILTER (WHERE ...)` columns.

26. **Stripe webhook handler list has no entry for
    `checkout.session.completed`.** `src/app/api/webhooks/stripe/route.ts:36-39`
    only registers `customer.subscription.updated` and `.deleted`. But
    `src/lib/billing/handlers/checkout-session-completed.ts` is what the
    onboarding-welcome page comment (`onboarding/welcome/page.tsx:42`)
    says is responsible for atomically creating the org + member +
    subscription rows. If the file exists and isn't wired into HANDLERS,
    new subscribers stall on the welcome poller indefinitely.
    **Fix**: Confirm the handler is registered (the route file shown only
    listed two; verify against the HANDLERS map and add the missing
    entry).

27. **PWA shortcuts use locale-less paths.**
    `public/manifest.webmanifest:33,38` — shortcut URLs `/dashboard` and
    `/dashboard/properties/new` rely on the middleware to redirect to
    `/en/dashboard/...`. Works, but adds 30-307 redirect on every
    install-shortcut launch and English-defaults users whose
    `Accept-Language` is non-EN.
    **Fix**: Render per-locale shortcuts at runtime (or accept the EN
    default — but document).

28. **Offline page hardcoded to `lang="en"`.**
    `public/offline.html:2` — non-EN users hit network outage → see
    English-only fallback. Same file is precached, so even a Spanish
    PWA agent loses connectivity and gets EN copy.
    **Fix**: Either render multiple per-locale offline pages and serve
    the matching one based on the active locale cookie, or at least
    make the copy locale-detect from `navigator.language`.

29. **City landing canonical built without normalising the country slug
    case.** `src/app/[locale]/properties-in/[country]/[city]/page.tsx:77-78`
    interpolates `${country}` directly. Lowercase is implied but not
    enforced — visitors hitting `/en/properties-in/DO/santo-domingo`
    get a canonical URL with `DO` (uppercase) while sitemap emits
    lowercase, splitting SERP authority.
    **Fix**: `country.toLowerCase()` before interpolation, or 301 to
    the canonical case.

30. **`citySlug()` doesn't strip Latin diacritics correctly.**
    `src/lib/listings/search.ts:234` uses NFD then
    `.replace(/[̀-ͯ]/g, '')` — that range string isn't a valid combining
    diacritical block in JS regex; it captures U+0300–U+036F only by
    accident of the source-file encoding. "São Paulo" → "so-paulo"
    silently per the code comment, which means Brazilian agent listings
    get broken canonical city URLs.
    **Fix**: Use `.replace(/[̀-ͯ]/g, '')` (explicit unicode
    range) and consider Postgres `unaccent` extension for DB-side
    normalisation.

31. **Hero search submits city by display name, not slug.**
    `src/components/home/hero-search-form.tsx:163` — `<option
    value={opt.city}>` (the display name). Combined with #1, this means
    the entire homepage hero search is fragile to any DB-side casing
    diff.
    **Fix**: Switch the option value to `citySlug` and resolve to a
    `/properties-in/{country}/{city}` direct landing instead of
    `/search?city=...`.

## P2 — rough (works but unpolished)

32. **Loading boundaries only exist for 3 surfaces.**
    Only `/search`, `/dashboard`, and `/properties/[slug]` have
    `loading.tsx`. Locale-aware skeletons missing on
    `/properties-in/[country]/[city]`, `/agents/[slug]`,
    `/saved-searches`, `/saved-properties`, every dashboard subroute,
    every admin tab. Slow Supabase round-trips show a blank page.

33. **Admin pages bypass i18n entirely.** `/admin`, `/admin/users`,
    `/admin/orgs`, `/admin/leads` all hardcode English UI labels even
    when accessed via `/es/admin`. Admins switching locale see ES nav
    chrome but EN page bodies. Non-blocker but inconsistent — this is
    documented as "admin = internal" but admin/leads contains data the
    admin will paste into customer comms.

34. **Locale switcher aria-pending state missing.**
    `src/components/locale-toggle.tsx:62` — sets internal `isPending`
    but only `disabled` reflects it. A screen reader user gets no
    feedback that the switch is in flight.

35. **SaveSearchButton has no `aria-live` region.**
    `src/components/saved-searches/save-search-button.tsx:80-86` —
    "Saving / Saved / Error / Idle" state changes have no live-region
    announcement; the visible text inside `<button>` flips silently.
    The 4-second auto-revert is also too quick for AT users.

36. **Property detail page has many `eslint-disable @next/next/no-img-element`
    blocks** (lines 467, 285, etc.) instead of using `next/image`.
    Acceptable for `imagedelivery.net` (CF Images) but the comment
    suggests they bypassed Next's optimisation deliberately. LCP impact
    on slow networks.

37. **Voice import notice "queued" doesn't auto-dismiss when the queue
    drains.** `src/components/listings/import-panel.tsx:333` — the
    `setQueuedNotice` only fires on `aho:voice-queue-flushed` with
    uploaded > 0. If the user backgrounds the tab and the queue
    drains via SW, the queued counter goes to 0 but the older "Saved
    — we'll upload…" banner persists.

38. **"Translation pending" warning rendered with `role="status"`** on the
    property detail page (`page.tsx:295`) — should be `role="note"` or
    `role="alert"` depending on intent. `status` is for live polling.

39. **Hardcoded `'You can\'t change your own admin status'` tooltip on
    AdminToggleButton** (`admin-toggle-button.tsx:37`) — fine for
    admin, but inconsistent with the rest of the i18n strategy.

40. **Pricing page constants drift risk.**
    `src/app/[locale]/pricing/page.tsx:24-28` — `PRICING_USD` map is a
    second source of truth for plan amounts (Stripe prices being the
    first). Code comment acknowledges. If someone edits the Stripe
    products without updating this constant, the JSON-LD `Product`
    nodes lie to Google.

41. **Hero search form `useEffect([country])` resets `city` to ''**
    (`hero-search-form.tsx:62-87`) but the lint rule for exhaustive
    deps would flag the missing `setCity` / `setCities` /
    `setCitiesLoading`. They're stable setters so this is OK, but the
    eslint pragma is missing.

42. **"All", "New", "Active", "Draft", "Pending", "Archived" filter chips
    untranslated** on `/admin` (line 569-573) and `/admin/leads`
    (141-146). Same story as #33.

43. **Admin overview "Recent activity" empty-state copy hardcoded EN**
    (`admin/page.tsx:528`). Same risk as the rest of admin.

44. **Manifest `start_url: "/"` triggers an extra middleware redirect**
    on every PWA cold launch. Non-blocker but free perf win to set it
    to e.g. `/en` or per-locale.

45. **`role="search"` on the hero form is correct** but the form's
    accessibility-name comes from the eyebrow text, not from any
    explicit `aria-label`. Screen readers may announce "search form"
    only.

## What I tested vs couldn't test

### Tested via source review
- Every route under `src/app/[locale]/`
- Critical lib helpers (`search.ts`, `favorites.ts`, `translate-path.ts`,
  `admin-mfa.ts`, `routing.ts`, `lead-routing rules`)
- Middleware, sitemap, robots, manifest, service worker
- Major API endpoints (leads POST, favorite POST, billing portal,
  stripe webhook, admin toggle-admin, photo-import-failures)
- All 7 locale message catalogs (size/coverage diff)
- Database migration headers + RLS comments

### Could NOT test (no browser, no network)
- Live HTTPS responses (sitemap XML validity, JSON-LD validity, OG
  preview rendering, hreflang headers)
- Lighthouse / Web Vitals deltas claimed by recent commits
- Service worker `flushVoiceQueue` behavior in real Chromium
- Stripe Customer Portal redirect chain (test mode is not exercised)
- Real Meta OAuth callback (third-party blocked)
- MediaRecorder voice-import on Safari iOS
- PWA install prompt on Android Chrome
- Map view zoom + bbox-driven re-fetch on Leaflet
- Mobile viewport rendering (CSS-only assertions can't be made
  statically)
- Email deliverability (Brevo DKIM is a PO action per CLAUDE.md)
- Whether `checkout.session.completed` is actually wired into HANDLERS
  — only saw the file referenced in route comments; recommend a quick
  `grep` against the actual map.

### Suspicions worth a manual pass
- Race condition: lead-routing `lead_routing_state` upsert (route.ts
  line 274-285) is non-atomic with the rule selection — under high
  concurrency two leads could land on the same agent.
- The `properties.city` column appears un-indexed in the migrations
  scanned — combined with #1 the homepage search may table-scan once
  inventory grows.
- The N+1 patterns in admin pages (#24, #25) will get progressively
  worse as orgs/users scale; the page might silently exceed the 30s
  Cloudflare Workers CPU budget.
